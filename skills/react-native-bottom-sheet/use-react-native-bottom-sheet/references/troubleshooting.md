# Troubleshoot sheet integration

Identify the installed `@swmansion/react-native-bottom-sheet` version, platform, and presentation mode. Use the checks below as starting points based on documented behavior. Several causes can produce the same symptom.

| Symptom | Check |
| --- | --- |
| Missing native view or codegen error on iOS or Android | Verify the React Native and React versions, Fabric, and that the running native build includes the library. For Expo, check that you're using a development build rebuilt after installing the package. For bare iOS, check that pods were installed. [Requirements](https://docs.swmansion.com/react-native-bottom-sheet/docs/getting-started/#requirements) · [Expo rebuild guidance](https://docs.expo.dev/develop/development-builds/introduction/#rebuild-when-native-code-changes) |
| Default modal sheet is missing or reports a provider error | Check that the component rendering it is under `BottomSheetProvider`. The provider is optional for inline sheets and `windowOverlay`. [Installation](https://docs.swmansion.com/react-native-bottom-sheet/docs/getting-started/#installation) |
| Sheet is behind a native modal or loses screen context | Use `windowOverlay` when the sheet needs to cover a native modal. For a default portal, put shared context above `BottomSheetProvider` or pass the needed values or navigation callbacks from the sheet owner. [Window overlay](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#window-overlay) · [React context](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#react-context) |
| Sheet body is transparent or its background disappears as content shrinks | Check that the background is in `surface` and fills its host, for example with `StyleSheet.absoluteFill`. Use `surfaceStyle` for corner radii and supported shadows. [Surface](https://docs.swmansion.com/react-native-bottom-sheet/docs/surface/) |
| Sheet reverts after a user snap, or detent changes cause an error | Check that `onIndexChange` updates the controlled `index`. Use `onSettle` for work after movement ends. When shortening the detent array, keep the index in range in the same render. If the issue appears on resize, check whether resolved detent heights plus bottom insets still ascend. [Detents and index](https://docs.swmansion.com/react-native-bottom-sheet/docs/detents-and-index/) |
| Content-sized sheet fills the host, or a list can't reach its last row | A filling list at the tallest `'content'` detent uses the available height. Use a fixed or percentage upper detent for a smaller viewport. If rows are unreachable, check the list's measured viewport and whether its parents constrain its height. [Detents and index](https://docs.swmansion.com/react-native-bottom-sheet/docs/detents-and-index/) · [React Native ScrollView](https://reactnative.dev/docs/scrollview) |
| The list reaches its start during a downward drag and the sheet stays open | By default, `collapse: 'initial'` keeps the gesture with the list if it began while scrolled. Check whether a new drag from the visual start collapses the sheet. Use `collapse: 'handoff'` for a continuous drag into a lower detent. For custom Android scrollers, check nested-scrolling support. [Scroll coordination](https://docs.swmansion.com/react-native-bottom-sheet/docs/scroll-coordination/) |
| Keyboard covers a control, adds extra space, or delays a height change | Check which part of the app handles keyboard overlap in the active host. If app-animated padding changes the measured `'content'` height, use `animateContentHeight={false}`. If tapping a scrollable child only dismisses the keyboard, check `keyboardShouldPersistTaps`. [Keyboard handling](https://docs.swmansion.com/react-native-bottom-sheet/docs/keyboard-handling/) · [Tap behavior](https://reactnative.dev/docs/scrollview#keyboardshouldpersisttaps) |
| Scrim tap, Back, Escape, or screen-reader dismissal leaves the modal open | Check whether `onCloseRequest` updates app state when it should close. Default dismissal requires positive current scrim opacity and a non-programmatic closed detent. Scrim and screen-reader requests require positive opacity even with transparent color. For Back or Escape, check stack order, whether the top sheet is still visibly closing, and whether a `'content'` target has measured above zero. For Android portal Escape, check where focus is. [Close requests](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#close-requests) · [Accessible dismissal](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#accessible-dismissal) · [Target eligibility](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#target-eligibility) |
| Form resets on reopening or position events stop after close | Check `lazy`. It unmounts sheet content after settling closed, clearing local state and suspending position events until reopening. Keep the default mounting behavior if the content should stay mounted while closed. Use `onSettle` to observe closure. [Lazy content](https://docs.swmansion.com/react-native-bottom-sheet/docs/modal-sheets/#lazy-content) · [Position tracking](https://docs.swmansion.com/react-native-bottom-sheet/docs/position-tracking/) |
| Final-frame jump or iOS stutter while settling | Check the installed version against the changelog. Version 1.1.0 fixed a final-frame jump on iOS, Android, and web and reduced settling stutter on iOS. [1.1.0 changelog](https://swmansion.com/changelog/react-native-bottom-sheet-1-1-0/) |
